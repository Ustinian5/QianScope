# 黔镜 QianScope 产品需求基线：问卷驱动的通用事件预测

> 状态：生效中（Canonical）  
> 生效日期：2026-08-24  
> 优先级：本文件是后续产品设计、架构、开发和验收的最高优先级依据。若与
> `README.md`、`prompt.md`、旧 backlog 或现有页面产生冲突，以本文件为准。

## 1. 产品定义

黔镜 QianScope 是一个**问卷驱动的通用社会事件预测系统**。

用户通过简单的分步问卷描述：要研究的事件、目标人群、已知事实、希望询问的
问题和预测时间范围。系统从不少于 5,000 个稳定人格 Agent 中选择目标人群，先
预测每个 Agent 的问卷回答，再模拟事件曝光、Agent 互动和状态变化，最终输出：

- 预测问卷结果；
- 不同人群的反应差异；
- 未来反响和行动的概率；
- 反应随时间的变化；
- 传播、共识、分化等群体现象；
- 不确定性、关键影响因素和可验证回放。

产品可以服务社会研究、公众态度研究、文化与教育研究、社区议题、产品研究等
场景，但**不得把营销、商业、市场、城市政策或特定行业作为默认产品叙事**。

本项目追求与境瞳科技公开产品相近的功能作用和用户效果，但采用 clean-room
方式自主实现，不复制其非公开代码、模型权重、数据、品牌或视觉资产。

## 2. 已锁定的产品原则

1. **Agent 是核心，不是装饰。** 模拟结果必须由人格 Agent 的状态、行为策略、
   记忆和关系共同产生，不能只把 Agent 数量显示在页面上。
2. **默认运行 5,000 个 Agent。** v1 每个正式预测运行至少包含 5,000 个稳定人格
   Agent，并预留扩展到 20,000 个以上的批处理接口。
3. **问卷是主要入口。** 用户不需要理解危险率、蒙特卡洛、状态转移等术语，只需
   按步骤回答问题或导入问卷。
4. **通用事件优先。** 核心契约不得硬编码市场、企业、政策、城市或营销字段。
5. **概率优先。** 输出必须包含概率分布、群体分布和不确定性，不能只给单一结论。
6. **人格一致性优先。** 同一 Agent 在相同背景下的回答和行为应保持可解释的一致性，
   事件和互动可以改变其动态状态，但不能无原因随机换人格。
7. **简单产品、复杂内核。** 技术细节放入“高级信息”，主流程只展示用户需要做的
   决策和结果。
8. **可校准、可回放。** 预测必须能与后续真实问卷或事件结果对比，并能重放每次运行。

## 3. P0 核心能力

### 3.1 人格 Agent 人群底座

v1 必须提供不少于 5,000 个可持续复用的 Agent。每个 Agent 至少拥有：

- 稳定 ID 与数据来源；
- 人口统计与社会角色；
- 人格特质、价值观、兴趣和生活目标；
- 当前信念、态度、情绪、信任和风险偏好；
- 信息渠道与媒介使用习惯；
- 决策风格、表达倾向和行动倾向；
- 工作记忆、事件记忆和长期记忆引用；
- 家庭、熟人、同事、社区和线上关系；
- 每个字段的 observed / inferred / synthetic 来源标记。

人格 Agent 可以来自获得授权的调查与人口数据，也可以来自有统计约束的合成人口。
禁止用一段随机 Persona 文本冒充人格底座。

默认 5,000 Agent 的运行分层固定为：

| 层级 | 默认数量 | 执行方式 |
|---|---:|---|
| Key Agents | 50 | LLM 或高能力策略，处理高影响、高不确定性行为 |
| Representative Agents | 450 | 蒸馏模型、轻量模型或受约束策略 |
| Background Agents | 4,500 | 向量化统计策略和概率状态转移 |

三个层级必须实现同一 `observe -> decide -> act -> remember` 契约。是否调用 LLM 不影响
其 Agent 身份；不得为每个 Agent 启动独立常驻进程。

### 3.2 问卷预测

系统必须支持用户创建或导入问卷，并让目标 Agent 人群回答。P0 问题类型包括：

- 单选；
- 多选；
- 量表；
- 排序；
- 数值题；
- 开放题。

每道结构化问题至少输出：

- 每个 Agent 的选项概率；
- 加权总体分布；
- 主要人群分组结果；
- 置信区间或预测区间；
- 关键影响因素；
- 缺失信息和超出分布警告。

开放题由代表 Agent 或 Key Agent 生成，系统同时提供主题聚类和代表性回答，不把大量
随机文本直接当成结论。

系统必须同时支持：

1. **基线问卷**：预测事件发生前的人群状态；
2. **事件后问卷**：预测事件发生后或不同情景下的回答变化；
3. **真实结果回填**：导入真实问卷结果，评估和校准预测。

### 3.3 通用事件预测

事件模型只要求以下通用信息：

- 发生了什么或可能发生什么；
- 涉及哪些主体；
- 哪些人可能接触到该事件；
- 已知事实、证据及其时间；
- 需要预测的反应或结果；
- 预测时间范围；
- 可选的对照情景和替代情景。

系统必须能够预测：

- 知晓、相信、支持、反对、观望等态度分布；
- 情绪、信任、意愿和行为倾向变化；
- 分享、讨论、沉默、参与、退出等通用行动；
- 不同人群的异质性反应；
- 信息扩散、共识、分化和关键节点影响；
- 候选后续事件的发生概率、时间窗和事件链；
- 对照情景与替代情景之间的概率差值。

事件类别、行动集合和观测指标由问卷与场景动态定义。现有市场事件、苏州城市和价格
实验只能作为示例适配器，不能继续占据产品主入口。

### 3.4 多 Agent 社会运行时

每个模拟 tick 按以下顺序运行：

```text
事件和环境更新
  -> Agent 按关系与渠道获得不同信息
  -> Agent 根据人格、记忆和当前状态形成回答/行动分布
  -> Agent 采取行动并与其他 Agent 互动
  -> 互动更新信念、情绪、信任、记忆和关系
  -> 聚合群体状态并进入下一 tick
```

P0 必须实际支持：

- Agent 到 Agent 的信息传播；
- 支持、反对、分享、讨论、沉默等通用互动；
- 关系强度、信任和同质性对传播的影响；
- Key Agent 的放大或阻断效应；
- 多轮状态更新；
- 固定随机种子的确定性回放；
- 多条随机路径形成的不确定性区间。

只有选择出 Agent 层级、但未让 Agent 策略参与主循环，不算完成多 Agent 模拟。

## 4. 唯一主产品流程

前端主流程固定为五步，基础模式不得增加更多必填步骤：

1. **描述预测目标**  
   用自然语言或引导问题说明事件、已知情况和希望预测的未来结果。
2. **选择目标人群**  
   选择预置人群、设置筛选条件，或上传合规的人群数据。
3. **填写或导入问卷**  
   定义希望 Agent 回答的问题；系统可以根据事件自动建议问题，但必须由用户确认。
4. **确认时间与情景**  
   选择时间范围、基线情景和可选替代情景，查看关键假设。
5. **运行并查看结果**  
   展示预测问卷、群体差异、未来反应时间线、不确定性和可导出的简明报告。

首页只保留：产品一句话说明、一个“开始预测”按钮、最近项目。不得把模型治理、运行时、
城市指标、危险率、路径数量等研究信息作为首页主体。

结果页的默认阅读顺序固定为：

```text
一句话结论
→ 问卷预测
→ 群体差异
→ 未来反应与传播时间线
→ 关键影响因素
→ 不确定性与限制
→ 导出报告
```

运行清单、哈希、完整路径、模型参数和回放记录放在“高级信息”中。

## 5. 目标系统结构

```text
Questionnaire Wizard
  -> Population Service（5,000+ 人格 Agent）
  -> Survey Engine（事件前/后回答分布）
  -> Event Scenario Compiler（通用事件契约）
  -> Multi-Agent Runtime（观察、行动、互动、记忆）
  -> Forecast & Aggregation（群体分布、事件概率、时间线）
  -> Calibration & Replay（真实结果、评测、回放）
  -> Simple Report UI
```

现有组件的处理方式：

- 保留事件危险率、共同随机数、事件链和回放能力，作为底层预测组件；
- 保留苏州 World Adapter，但移出主导航，降级为高级示例；
- 保留统计问卷模型和 Agent 策略接口，并接入新的统一 Agent 主循环；
- 重做当前前端信息架构，不继续扩展研究仪表盘；
- 停止新增市场、组织、政策、城市专用的主产品字段和页面。

## 6. P0 数据契约与 API

最小统一对象：

- `AgentProfile`：稳定人格与来源；
- `AgentState`：可随时间变化的信念、态度、情绪、意愿和记忆；
- `Relationship`：关系类型、强度、信任和影响方向；
- `Questionnaire` / `Question`：问卷及问题定义；
- `EventScenario`：通用事件、证据、范围、时间和替代情景；
- `PredictionRun`：一次问卷与事件联合预测；
- `AgentResponse` / `AgentAction`：个体回答与互动；
- `PredictionResult`：聚合分布、时间线、不确定性和限制。

P0 API：

```text
POST /v1/populations/generate
POST /v1/questionnaires
POST /v1/predictions
GET  /v1/predictions/{run_id}
GET  /v1/predictions/{run_id}/replay
POST /v1/predictions/{run_id}/outcomes
```

`POST /v1/predictions` 是主入口，必须同时接受目标人群、问卷、事件和预测范围。城市、市场
等适配器可以保留独立 API，但不能成为前端依赖的唯一入口。

## 7. v1 验收标准

以下条件必须全部满足，才能称为“问卷驱动的多 Agent 通用事件预测 v1”：

### Agent

- 单次正式运行实际参与的稳定人格 Agent 不少于 5,000 个；
- 每个 Agent 有稳定 ID、人格状态、记忆状态和至少一类关系；
- 5,000 个 Agent 不是重复 Prompt 或页面数字；
- Key、Representative、Background 三层策略均真实参与运行；
- 同一输入与随机种子可复现相同结果。

### 问卷

- 用户可以在页面创建至少 10 道混合类型问题；
- 系统输出 5,000 个 Agent 的回答分布及加权汇总；
- 可以查看总体、至少三个自动发现或用户指定的人群分组；
- 支持事件前后问卷对比；
- 支持 CSV/JSON 结果导出和真实结果回填。

### 事件预测

- 用户可以提交任意通用社会事件，而不需要选择市场或政策模板；
- 至少支持 30 个 tick 的多轮互动；
- 输出群体反应时间线、主要分组、传播/互动结果和候选后续事件；
- 至少支持基线与一个替代情景；
- 多路径运行输出 P10/P50/P90 或等价不确定性区间。

### 前端

- 新用户只通过五步流程即可完成一次预测；
- 基础流程不出现危险率、Monte Carlo、模型版本和哈希等术语；
- 首页和默认示例使用通用事件，不使用市场、政策或苏州作为中心叙事；
- 结果页优先回答“人群会如何回答、如何反应、接下来可能发生什么”。

### 工程与可信度

- 结构化结果全部通过 Schema 校验；
- 固定种子回放验证通过；
- 单元、集成和端到端测试通过；
- 默认示例明确标记合成数据和未校准状态；
- 没有真实时间留出评测前，不宣称现实预测准确率。

## 8. 开发里程碑与顺序

后续开发严格按以下顺序推进，不先做新的大屏或垂直行业页面：

1. **M1：统一产品契约**  
   定义通用 Agent、问卷、事件、预测运行和结果 Schema，移除主流程领域硬编码。
2. **M2：5,000 Agent 人格底座**  
   生成、持久化、筛选和核验稳定人格 Agent 与关系网络。
3. **M3：问卷预测引擎**  
   完成结构化问题概率预测、开放题代表回答、分群汇总和事件前后对比。
4. **M4：多 Agent 通用事件运行时**  
   把三级 Agent 策略真正接入观察、行动、互动、记忆和状态更新主循环。
5. **M5：五步式极简前端**  
   用统一预测 API 替换现有研究工作台主流程。
6. **M6：校准、盲测和开源发布**  
   接入真实结果回填、时间留出评测、示例数据、部署和贡献者文档。

每个里程碑必须有可运行演示、自动化测试和清晰的未完成边界，不能用静态页面或随机
文本替代后端能力。

## 9. 明确不做

- 不复制或逆向境瞳科技的非公开实现、数据和视觉资产；
- 不把几千个独立 LLM 进程当作规模化 Agent 系统；
- 不建设 3D 元宇宙或数字城市可视化；
- 不把苏州、市场营销、组织决策或公共政策作为默认主产品；
- 不做无候选边界、无证据时间和无不确定性的“万能预言”；
- 不用随机生成的人格、回答或舆论文本冒充预测效果；
- 不对真实个人做重新识别、高风险决策或隐性操纵。

## 10. 最终完成定义

用户能够在一个简单页面中，逐步填写“研究什么事件、研究哪些人、想问什么、预测多久”，
系统真实调度至少 5,000 个稳定人格 Agent 完成问卷回答和多轮社会互动，并返回可解释、
可分群、带不确定性、可回填校准的未来事件反应预测。

达到这一结果，才算完成本阶段对境瞳公开产品核心作用和效果的功能复刻。
